# デザイン王国 — Phase 13: リリースチェックリスト

**バージョン:** 1.0
**リリース戦略:** v1.0は「エリア①のみの先行体験版」(Phase 12 §5の提案を採用)。ボス戦・ギルド・手紙ボックスはv1.1以降。

## 1. v1.0 スコープ確定(リリース判定の前提)

| 含む | 含まない(v1.1へ) |
|---|---|
| オンボーディング(世界観→目標→初依頼) | 登録UI(v1.0は匿名認証のみ。機種変引き継ぎはv1.1で本認証リンク) |
| エリア①のクエスト(目標: 40件をcontent/で量産) | エリア②〜⑧のクエスト(マップには表示・ロック状態) |
| AI添削(画像・6軸・リテイク) | 👍/👎ボタン、再添削UI |
| 受注予約・あと1クエスト・ストリーク・お守り(自動消費) | お守り購入UI・週間目標UI・宝箱開封UI |
| 世界マップ・エリア発展・プロフィール・スキル表示 | 装飾・スキル分岐・ポートフォリオ画像表示 |
| 設定・アカウント削除 | 手紙ボックスUI(通知はOSプッシュのみ) |

**判定基準:** 「毎日5〜10分、仕事をクリアして王国が育つ」コアループが完結していること。上記「含む」でループは閉じている。

## 2. ストア審査要件チェックリスト

### 共通
- [ ] プライバシーポリシーURL(docs/privacy_policy_draft.md を法務レビュー後に公開)
- [ ] 利用規約URL
- [ ] お問い合わせ先(サポートメール/フォーム)
- [ ] アカウント削除がアプリ内から可能(実装済み: 設定→2段階確認→全データ削除)
- [ ] 年齢レーティング: 4+/全年齢(暴力・課金・広告なし)。**ただし利用規約で13歳以上を推奨**(COPPA/個人情報の観点、法務確認)
- [ ] AI生成コンテンツの明示: 添削がAIによるものであることをオンボーディングまたは添削画面に表記(ストア方針対応)

### App Store固有
- [ ] ATT(App Tracking Transparency): **不要**(トラッキングなし・広告なし)。App Privacy設定で「トラッキングなし」を申告
- [ ] App Privacy(収集データ申告): メール(本認証導入後)/写真(提出画像・ユーザー起点のみ)/識別子(匿名UID)/使用状況データ(Analytics) — 各「アプリ機能」目的、トラッキング用途なし
- [ ] Sign in with Apple: v1.0は匿名のみのため不要。**v1.1でGoogleログインを入れる際は必須になる**ことを計画に明記
- [ ] 審査ノート: テスト手順(オンボーディング→マルコ依頼→画像提出はサンプル画像で可)、AI添削の説明、review_daily_limitの存在

### Google Play固有
- [ ] Data safety フォーム: 上記App Privacyと同内容
- [ ] ターゲットAPIレベル最新要件の確認
- [ ] 内部テスト→クローズドテスト(20人規則対応)→製品版の順

## 4. 段階リリース計画

| 段階 | 対象 | 期間 | 合格基準(次段階へ) |
|---|---|---|---|
| 内部テスト | チーム+関係者10名 | 1週 | Phase 12 QAチェックリスト全通過、クラッシュフリー率99.5% |
| クローズド | 招待50名(ターゲット層) | 2週 | 初日納品率50%以上、添削の重大トーン事故ゼロ、D7=30%以上 |
| 公開(段階配信) | Play 10%→50%→100% / iOS通常 | 2週 | クラッシュフリー維持、costGuard発火なし |

## 5. リリース後の監視(初週デイリー)

- ノーススター: 週あたり納品クエスト数 / ファネル: オンボ完了率80%・初日納品率60%(Phase 1 KPI)
- AI添削: レイテンシp95(<40s)、失敗率(<5%)、日次コスト(costGuard閾値$50)
- アラート: ops_alerts、Crashlytics、Cloud Monitoring(Phase 6 §5.4)
- ロールバック手順: アプリ=段階配信停止 / コンテンツ=旧YAML再publish / プロンプト=旧version再投入(Phase 11 §4)
